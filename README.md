# Kiroku 記録

A local-first, block-based note editor that runs in your browser.

Your notes live in IndexedDB on your own machine. There are no accounts and no sync. The only thing that ever leaves the browser is an AI prompt, and only when you ask for one.

---

## Features

- **Block-based editing** — paragraphs, headings (H1–H3), quotes, code, todos, and dividers
- **Slash commands** — type `/` on an empty block to change its type, or after a space to insert a new block
- **Multi-page workspace** — sidebar navigation, editable page titles, two-click delete
- **Auto-save** — debounced writes to IndexedDB, with a best-effort flush when the tab is hidden
- **AI block generation** — type `/ai <topic>` and press Enter to insert structured notes, generated by Gemini through a serverless proxy and validated before they touch your page
- **Drag-and-drop reordering** — grab the `⠿` handle in the left gutter; works with mouse, touch, and keyboard (Tab to the handle, Space to lift, arrows to move, Space to drop)
- **Markdown export** — download any page as a `.md` file, or copy it to the clipboard. Title and icon are kept in front matter, and text that merely *looks* like Markdown (a paragraph starting with `#`, say) is escaped so it stays plain text
- **Keyboard-first** — Enter creates a block, Backspace on an empty block deletes it

## Getting Started

**Prerequisites:** Node.js and the [Vercel CLI](https://vercel.com/docs/cli) (`npm i -g vercel`).

```bash
npm install
```

**Editor only (no AI):**

```bash
npm run dev          # http://localhost:5173 — /api routes are not served
```

**Full app, including `/ai`:**

```bash
vercel link                      # once, to connect the project
vercel env add GEMINI_API_KEY    # once; choose the Development environment
vercel dev                       # http://localhost:3000 — frontend + /api together
```

Get a Gemini API key from [Google AI Studio](https://aistudio.google.com/). Restart `vercel dev` after adding or changing environment variables.

> **Never put the API key in a `VITE_` variable or anywhere under `src/`.** Vite bundles `VITE_` variables into the JavaScript that ships to every visitor. The key belongs only in Vercel's environment store, where server code reads it.

**Other scripts:**

```bash
npm run build     # type-check all three TS projects (tsc -b), then bundle
npm run preview   # serve the production build
npm run lint      # ESLint
npm test          # Vitest in watch mode
npm run test:run  # Vitest once (run before committing)
```

## Architecture

Kiroku spans two runtimes:

```
┌─ BROWSER (src/) ────────────────┐        ┌─ SERVER (api/, server/) ───────────┐
│  React → Redux → Services       │  HTTP  │  Route → AIService → LLMProvider   │
│  IndexedDB (all note data)      │ ─────► │  Holds the API key. Calls Gemini.  │
└─────────────────────────────────┘        └────────────────────────────────────┘
             └────────── shared/ (types both sides agree on) ──────────┘
```

- **`src/`** — the React app. Components → Redux store → services → IndexedDB.
- **`api/`** — serverless entry points. Every file here is a public URL, so only routes live here.
- **`server/`** — logic the routes import: the generation pipeline, the provider interface, and the response validator.
- **`shared/`** — types both sides need. Browser code never imports from `server/`.

A few design decisions worth knowing:

- **One home for persistent data.** Pages and their blocks live in a single Redux slice; the other slices hold only transient UI state.
- **Ids, not positions.** Every block operation targets blocks by id, so an AI insertion still lands in the right place even if its trigger block is dragged mid-generation.
- **Model output is untrusted input.** The server validates every block the model returns and rebuilds clean objects from verified fields only. One malformed block rejects the batch, and the request is retried.
- **Provider-agnostic AI layer.** Code talks to an `LLMProvider` interface; Gemini is one implementation. Adding another provider touches two marked places.
- **The browser mints blocks; the server only describes them.** The server returns `{ type, content }` intents. Ids and timestamps are created in exactly one browser-side factory.
- **Pure core, thin edges.** Markdown export is a set of pure, unit-tested functions (escaping, block conversion, filenames); the code that touches the browser — the download and the clipboard — is a thin wrapper around them.

See [`CLAUDE.md`](CLAUDE.md) for the detailed architecture, conventions, and known gotchas.

## Known Limitations

- **Todo and code blocks render as plain text for now.** There is no checkbox yet and code has no syntax highlighting; dedicated components are planned for Phase 9.
- **Export is one-way for now.** Markdown import is planned for V2.
- **Some formatting doesn't survive export:** empty blocks are skipped, and line breaks inside a heading become spaces (a Markdown heading is a single line).
- **Switching pages while AI is generating** can put the generated blocks on the page you switched to. A fix is planned for Phase 9.
- **Test coverage is partial.** Unit tests cover the Markdown export pipeline; Redux, the AI flow and end-to-end tests come in Phase 10.
- **After a mouse drag, click the block to resume typing.** Text is preserved; the caret is not restored.
- **Single-device only.** There is no sync, by design.
